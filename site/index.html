The problem

A device can expose more than its platform profile admits.

Smart-home platforms need driver artifacts that turn protocol-level behavior into platform-level capabilities. When those artifacts are incomplete, opaque, or platform-specific, useful device attributes can disappear at the boundary.

EdgeLoom works at that artifact boundary. It makes profiles and capability maps inspectable, provides controlled transformations, and routes generated artifacts through shared schemas.

Scope matters. EdgeLoom currently works with SmartThings Edge driver artifacts and a Home Assistant-to-SmartThings translation path. It does not modify device firmware, replace either platform, package drivers, or install code on a hub.

Core capabilities

One CLI. Five ways to work with the artifact layer.

Each command is deliberately bounded. EdgeLoom produces, transforms, inspects, or checks artifacts; the operator remains in control of review, packaging, and installation.

01 / assurance gate

Validate

Check device profiles and capability maps against the same versioned JSON Schema contracts. A run fails on invalid documents — and on finding nothing to check.

edgeloom validate . Inspect schema v0.1 →
02 / reversible change

Patch + Restore

Expose mapped attributes in a local SmartThings Edge driver. Patch backs up first and rolls back on failure; restore parks the patched tree before returning to stock.

edgeloom restore ./zigbee-lock Read the patching guide →
03 / platform bridge

Translate

Query supported Home Assistant entities and generate SmartThings Edge proxy profiles and configuration for lights, switches, locks, and selected binary sensors.

edgeloom translate --ha-url … Explore the translator →
04 / ecosystem view

Discover

Scan a GitHub repository or local catalog, enumerate driver fingerprints, summarize devices, and flag drivers with no capability mapping yet.

edgeloom discover --source github Read discovery docs →

Design principle

Treat the profile as a checked contract.

Patch and translate take different routes, but their profile artifacts converge on the same schema. Validation becomes an assurance layer between transformation and hub installation — not an afterthought tied to one code path.

Industry + standards potential

A shared artifact layer can make cross-platform questions concrete.

EdgeLoom is early, but its schemas, catalogs, reversible transforms, and public evidence can support useful conversations across the smart-home ecosystem.

01

Device manufacturers

Reproduce how protocol attributes become platform capabilities and identify gaps worth addressing in drivers or documentation.

02

Platform maintainers

Review generated changes as explicit artifacts, validate them against shared rules, and use real device reports to prioritize coverage.

03

Integrators

Inspect the assumptions at a Home Assistant–SmartThings boundary and keep generated profiles under the same validation gate.

04

Standards communities

Use concrete profile and capability-map examples to study namespace alignment, portability, and future Matter-facing contracts.

05

Security researchers

Study hidden-attribute exposure, trust boundaries, generated code, and driver-supply-chain behavior with reproducible tooling.

06

Smart-home users

Preview and diff local changes, retain backups, restore a prior tree, and report real-device outcomes back to the project.

Getting started

From install to a checked artifact in two commands.

EdgeLoom requires Python 3.11 or newer. Install the published package, then validate a profile tree.

Command overview Development setup PyPI package
Quickstart
# Install the latest release
$ pip install edgeloom

# Check profiles and capability maps
$ edgeloom validate .
# exits non-zero on a failure or an empty check
  • edgeloom patch DRIVER MODEL MANUFACTURER [ATTRIBUTES]Preview with --dry-run before writing.
  • edgeloom restore DRIVERReturn to the sibling backup and preserve the patched tree.
  • edgeloom translate --ha-url URL --output DIRPrefer --no-token and supply credentials on the hub.
  • edgeloom discover --source github|localEnumerate fingerprints and mapping gaps.
Pre-1.0 safety note

Review diffs before installing any generated driver on a hub you depend on. Treat driver input and remote responses as untrusted, and keep Home Assistant tokens out of logs and version control.

Research → infrastructure

From a hidden-attribute finding toward a durable open ecosystem.

EdgeLoom accompanies research on hidden attributes in smart-home devices. Its longer-term direction is to turn that insight into maintainable public infrastructure: shared contracts, reproducible transforms, real-device evidence, and a governance model that can outlast one paper or institution.

Research vision

Make driver/profile mismatches measurable across platforms, protocols, and device classes while keeping claims tied to inspectable artifacts.

Broader impact

Help users regain visibility, help developers reason about generated drivers, and help ecosystem participants discuss portability with concrete evidence.

Sustainability

Grow through versioned schemas, public releases, contributor pathways, device reports, explicit stewardship, and reviewable technical decisions.
