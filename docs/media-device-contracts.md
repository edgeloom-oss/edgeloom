# Media and appliance evidence — draft contract v0.2

Draft development implementation, not a published standard or new device adapter.
Core owns contracts, validation and rendering; the catalog owns curated data.
Public adoption requires the normal governance/design-review process.

## Versioned addition, not silent migration

The original device and bundle schema files remain byte-for-byte unchanged.
Opt in with `schema_version: "0.2"`; validation selects separate
`catalog-device.v0.2.schema.json` and `device-evidence-bundle.v0.2.schema.json`.
Unknown versions fail closed. All other contracts remain v0.1.

| Field | Meaning | Not a claim of |
| --- | --- | --- |
| `protocol` | Broad classification: zwave, zigbee, ip, matter, other, unknown | Driver support or Matter conformance |
| `identity_scope` | exact-model or device-family | Physical inspection or compatibility |
| `category` | Human-facing grouping | Complete device coverage |
| `connections[].transports` | Declared bearers, or only unknown | A detected household connection |
| `application_protocol` | Source-described API/protocol | Protocol equivalence |
| `platform`, `integration`, `platform_version` | Examined adapter context | The user's installed version |
| `access`, `data_updates` | Local/cloud/hybrid dependence and update class | Observed connectivity, latency or privacy guarantees |
| `basis`, `references`, `limitations` | Source-declared evidence and scope | Hardware validation or independent review |

Family entries require a `family` identifier. Typed identifiers exclude IP,
MAC, serial, tokens and household names; free text still needs privacy review.
`unknown` cannot be mixed with known transports. Connections require unique IDs
and resolvable pinned-source references. A push classification may coexist with
a recovery timer: record that condition rather than erase it.

## Direct source evidence

v0.2 adds `features[].source_references` for single-source explanations. Each
feature needs a mapping, corroboration or direct source reference. Catalog and
bundle loaders resolve manifest/artifact IDs; package closure includes every
cited source. A locator is a reviewable assertion, not automatic proof of a
code claim. Do not invent a second platform comparison to satisfy the shape.

Source-only explanations have no independent-review or hardware status. Official
integration documentation is not a manufacturer's manual; community integration
source remains community evidence. These distinctions survive packaging.

## Joins, reports and packaging

The v0.2 bundle subject requires identity scope. Joining a family device to an
exact-model bundle is rejected. Legacy subjects without scope retain their
legacy model-declaration interpretation; they cannot silently absorb a family.
Existing protocol-mismatch, record-hash and reference-closure checks remain.

Archives include exactly the schema versions used by their records. Archive
format remains `device-evidence-bundle/0.1`: container and record versions are
separate. Verification compares trusted schemas and re-derives reports;
replacing and rehashing a schema is insufficient. Old verifiers reject v0.2.
Use the declared core pin. Renderer changes can change generated bytes; preserve
frozen older packages and their tool pins instead of rewriting history.

HTML/Markdown show scope and declared integration context. Browser search
includes connection terms; protocol filters derive from actual entries.
Device/family counts are evidence inventory, not adoption or supported devices.

## First candidate and limits

The LG webOS case traces power, availability and screen state in pinned Home
Assistant Core 2026.10.0 sources. It is an integration-family study, not a G2
qualification. Client state decoding, exact-model manufacturer manual, installed
versions, firmware, physical observations and independent review remain gaps.
No upstream source is executed or redistributed.

This increment does not extend observation or mapping contracts to IP/Matter.
Do not encode a TV observation as a v0.1 Zigbee subject. Those records need
separate design/review before acceptance. Descriptive schema support adds no
scanner, driver, HA connector, credential access, pairing, wake, media control
or appliance actuation.

## Verification

Run the full suite including `tests/test_media_catalog.py`, build a wheel and
validate from an isolated installed copy. Check mixed versions, unknown versions,
missing references, scope mismatch, duplicate connections, unsafe text,
source-only features, repeated byte-identical builds and offline verification.
Confirm legacy schema/data bytes are unchanged and inspect desktop/mobile reports.
